# Cloud-confirmed logout and optional memory level

**Kaydet ve çıkış yap** appears in the navigation for teachers and students. It saves the current notebook, waits for ongoing sync, uploads the latest copy, and reads it back from the server. The read-back copy must match the device state and account before Firebase sign-out and removal of this app's `yks_` storage entries. Other applications' storage is preserved. Both Firebase authentication sessions are signed out. Reloading returns to the login screen.

Offline, rejected, timed-out or conflicting writes, a mismatching read-back, account changes and failed sign-out keep the local notebook. The status offers retry or return to work. Unsaved results, settings, recovery rows and typed new work names must be saved first. Persistent weekly plan edits are saved automatically during logout; read-only previews close automatically. Another open updated tab prevents cleanup through a Web Lock; close it and retry. Browsers without Web Locks keep the notebook and explain that secure logout is unavailable. Teacher backups use the existing conflict protection. Student logout requires a published, recoverable account rather than an anonymous file-only session. See `logout-reset.md` for browser-only reset and reversible teacher cloud rollback.

Students can choose **Başlangıç hafıza düzeyin** in Settings; teachers can set it per student in Students. Normal is the unchanged default. Strong uses a 7-day starting interval, Very strong 14 days, and a single test on an untested topic. The configured maximum interval still applies. Topic-reset/relearning dates stay in effect.

These are optional self-reported scheduling assumptions, not measured memory capacity. The choice does not create results or mark work Easy. It changes initial stability for actual Good/Easy results (7/14 days for Strong; 14/28 for Very strong). Failed/Hard initial results keep the normal defaults; subsequent real results drive the existing FSRS updates. Learned subject parameters take precedence. Existing cards backed by results are recalculated; result history and issued plan slots/question totals remain unchanged. Unissued plan caches are rebuilt. Returning to Normal restores the ordinary initial assumptions, and the selection travels with backups, student packages and cloud work sync.

Validation covers server confirmation ordering, failure retention, retry, local cleanup, multi-tab protection, memory defaults, actual weak results, calibrated subjects, frozen plans, reset dates, package sync and fresh login after logout. Browser tests use synthetic accounts and mocked network failures. Firebase emulator tests run the real save/read-back and fresh-login data flow with the repository's rules.
