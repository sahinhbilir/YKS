# Code review — 9 September 2026

Reviewed default-branch commit `983f08c3a31562e256ddb04e2e13c180e34fb3f3`, including student and teacher flows, package imports, local persistence, result sync, Firestore rules, and existing tests. The patch addresses three reproducible data-integrity failures. Authentication and account ownership need follow-up work.

## Fixed in this branch

| Priority | Finding | Impact and change |
| --- | --- | --- |
| High | Student packages changed custom-topic IDs without updating saved plans. | Sparse teacher topic IDs were compacted on import, while weekly plan slots retained the old IDs. Assigned work could disappear, refer to another topic, or crash rendering. Export now includes topics referenced only by manual work, replacement slots, catch-up settings, and parent relationships. Import remaps those references consistently, preserves free-task IDs, and rejects missing topic definitions before replacing the notebook. Unrelated custom-topic labels from older packages are discarded. |
| High | Result-file imports preferred a student number over the remaining identity fields. | A file with an existing number but another name/class could update the wrong student's learning history. New exports carry the existing stable student ID when available. Imports use that ID, or require the supplied legacy identity fields to agree. The cloud importer retains its explicitly verified target. |
| Medium | Startup sorted unvalidated JSON by `rev` and `ts`. | A `null` source alongside a valid source threw before validation/fallback, preventing startup. Sorting now tolerates invalid source values so validation can skip them and load the valid backup. |

These changes preserve the existing package version numbers. Existing packages with sufficient topic definitions remain importable. A package missing the definitions needed to reconstruct its plan must be regenerated from the teacher's complete notebook; guessing those definitions would attach work to potentially wrong topics. Legacy result files with conflicting identity details are rejected rather than silently assigned. A stable student ID identifies a record; it is not authentication for a manually imported file.

## Highest-priority follow-ups

1. **Replace name-and-number-derived passwords.** `ogrenciGirisKimligi` generates the complete login credentials deterministically from the student's name and number. Hashing those public or guessable inputs does not add a secret. The same name/number in different classes or schools also produces the same account. Use independently generated credentials or an invitation/activation flow scoped to the school, with a recovery and migration plan for existing students. This requires changing the current login and provisioning flow, so this patch does not attempt an automatic account migration. [Current credential derivation](https://github.com/sahinhbilir/YKS/blob/983f08c3a31562e256ddb04e2e13c180e34fb3f3/index.html#L483-L510)

2. **Enforce teacher ownership on account-package writes.** The `ogrenciHesaplari/{uid}` create/update rule checks that the writer is an approved teacher, but does not require ownership of the current account document or its referenced result slot. An approved teacher who knows another account UID can overwrite or disable that account's package. Add an immutable owner identity and checks on both the current and destination slot, plus tests using two *approved* teachers. Existing documents need an owner backfill and the account-first publishing order must be updated with the rules. This is a source-level finding; deployed rules and production account access were not exercised. [Account-package rules](https://github.com/sahinhbilir/YKS/blob/983f08c3a31562e256ddb04e2e13c180e34fb3f3/firestore.rules#L82-L103)

## Reliability and maintenance improvements

- Add browser integration tests for login, opening a package, recording a result, reloading, and mobile print/export. The existing VM suites are useful, but their DOM/Firebase doubles cannot verify actual browser event behavior, Firebase session persistence, or App Check configuration.
- Split the approximately 500 KB `index.html` into catalog data, scheduling, import/export, persistence, authentication, and UI modules. Extract the import boundaries first; their array-index assumptions caused the failures reproduced here. Keep a build step for the standalone HTML export.
- Add a schema for the complete backup and every package type, especially weekly overrides and custom topics. Validate before persistence as well as import. Eventually use stable topic IDs to reduce the number of remapping paths.
- Add conflict handling for multiple tabs editing the same `yks_veri` storage key. Result transactions merge across devices, but local notebook writes still replace the whole stored document.
- Keep result-sync status distinct from full-backup status. Daily preferences and issued plans are not fully covered by result-only sync; make the backup/recovery path clear and test a new-device restore with those fields.
